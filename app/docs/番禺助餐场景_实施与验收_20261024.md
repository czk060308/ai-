# 安心接力：番禺临时助餐与取餐交接

2026-10-24。主线：补问需求→核实供餐→确认取餐人接受→记录取餐→记录交接→收集反馈。当前真实试点数为0；本轮验收全部使用合成演示，功能完成不代表完成真实助餐服务。

## 打开与演练

访问 http://127.0.0.1:8000/ ，默认进入助餐场景；原复诊页面在`/?scene=care`，历史需求、草案不覆盖。

1. 点击“载入合成助餐样例”，再点“使用合成字段”，不调用模型。也可点“AI识别并保存”调用已配置API，但记录用途仍是演示。
2. 核对日期、番禺地区、镇街、份数、交接截止、概略交接地、总预算、取餐人称呼/代号、可用窗口、单程分钟和家属饮食要求。约定取餐时刻不自动填写。
3. 样例可手工选12:05取餐并保存。任何字段变更都会使旧供餐核实和取餐人接受失效。
4. 右栏按服务镇街筛选公开名单，也可搜索名称/地址。选择同镇街资源，填写当天供餐窗口、总报价、核实方式和实际依据；代取、资格与饮食要求分别核实，开关默认不勾选。
5. 演练可填模拟11:00—13:00供餐、20元总价，备注必须写明“合成演练，没有联系商家”。不得将这些示例值用于真实服务。
6. 系统按已填供餐窗口、人员窗口、交接截止和单程时长求交集。样例可行取餐区间12:00—12:15，不含排队、路况与额外缓冲，不是到达保证。
7. 缺项、预算超额、时段无交集或供餐条件未确认时不能接受。条件满足后，填写记录人代号及确认依据，记录取餐人已接受。有空不等于接受。
8. 确实发生后依次记录取餐、交接，每步保存后清空进展草稿，不能跳步。
9. 交接后才可收集家庭反馈并完成闭环。满意度和实际支出可空，未知不变成默认好评或零费用。
10. 刷新或“重新载入”从数据库回读；导出JSON仅含统计和最小案例字段，不含原文、家庭代号、人员、详细地址、饮食备注和事件自由文本。

## 异常重排与状态边界

食堂停供、候选人没空等先记录受阻原因，再修改人员/时刻或重新选择同镇街资源，重新核实与接受。旧事件保留，新版本不能沿用旧接受，也不保留旧的有效取餐/交接状态。已取餐、已交接不能直接编辑安排，须先记录异常；完成和取消为终结状态。

每次操作带expected_version，在统一SQLite写事务中核对版本并保存事件；重复并发接受只有一次成功，其余返回409。操作者填报不是商家回执，没有自动拨号、发消息、预约、派单或付款。

## 真实试点操作卡

1. 接受真实家庭本来存在的需求，说明记录用途和模型处理方式，取得知情同意。不要为凑数制造需求。
2. 新建时选真实试点、填写家庭代号、勾选同意。同一家庭保持同一代号，不用姓名电话、身份证或病历。创建后的演示不能改成试点。
3. 通过手工或真实API建档；合成字段模式不能建真实试点。模型失败仍保存原文，可手工接续。
4. 历史电话/开放日只是线索。实际联系核实当天供餐、资格、打包代取、饮食要求和总价；不确定保持未知，不自行推算补贴价。
5. 候选人明确接受才记录接受；实际发生才记录取餐/交接。真实取餐与交接仅能记录当天服务，不能把未来安排提前记完成。
6. 反馈照实记录，评价可不提供。取消、受阻和未解决需求保留，不删失败美化成绩。
7. 系统统计依据是操作者填报，不独立证明履约；提交前逐条核对并按同意范围使用材料。

当前未获得社区授权或商家合作，没有家庭登录、对象级权限及商家回执接入，仅供本机开发与试点记录。原文会发给已配置模型供应商，请勿输入敏感个人资料。资源网页、历史联系方式和人工核实记录不进入模型提示词，不触发自动工具调用。

## 复现

仓库根目录执行：

```powershell
.\app\.venv\Scripts\python.exe -E -X utf8 -m pytest app/backend/tests -q
.\app\.venv\Scripts\python.exe -E -X utf8 app/scripts/import_panyu_resources.py
# API运行后：默认只做合成演练
.\app\.venv\Scripts\python.exe -E -X utf8 app/scripts/verify_meal.py
# 可选真实API，可能产生费用
.\app\.venv\Scripts\python.exe -E -X utf8 app/scripts/verify_meal.py --live
.\app\.venv\Scripts\python.exe -E -X utf8 app/scripts/verify_meal.py --live --injection
# 仅回读尚未修改的合成基线记录，不额外请求供应商
.\app\.venv\Scripts\python.exe -E -X utf8 app/scripts/verify_meal.py --recheck-case <case_id>
```

从app/apps/web目录执行`npm.cmd run build`和`npm.cmd run test:e2e`；浏览器验收前先启动API。

## 评估口径

需求数只含创建时标记pilot且确认同意的记录，演示永远排除；家庭按代号去重。闭环完成率为完成数/全部试点需求数，分母含待执行、取消和受阻。满意度均值以实际提供评分的反馈数为分母，未反馈不填默认分。没有基准测量就不算效率提升百分比，也不把联系次数、子任务数或演练次数当作服务家庭数。
