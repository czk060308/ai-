# 代码分类与阅读指南

## 推荐阅读顺序

1. 先看app/backend/src/anxin/domain.py，了解需求字段、未知值和演示输入。
2. 看model_gateway.py，了解真实调用、模型参数适配、原文证据及最多一次修正。
3. 看planning.py，了解确定性约束、事项模板、依赖及草案边界。
4. 看storage.py和main.py，了解数据事务、版本检查及HTTP入口。
5. 看app/apps/web/src/api.ts和App.tsx，了解页面如何读写服务端权威状态。
6. 最后看后端tests及前端e2e，确认每个行为怎样被验证。

## 后端模块职责

| 文件 | 负责什么 | 重要约定 |
|---|---|---|
| config.py | 从本机环境与.env读取配置 | 密钥不返回前端；默认数据库位于runtime |
| domain.py | Pydantic输入与需求Schema、缺项清单 | 未知值为null；NA等原文字面值不自动抹除 |
| model_gateway.py | 模型HTTP适配、JSON解析及原文依据核对 | 输出无依据则拒绝；最多一次修正，共享超时 |
| planning.py | 时段与预算规则、模板展开、事项DAG | 草案不产生预约；模型不决定规则是否通过 |
| storage.py | Need、Resource、PlanDraft、Event及会话 | 数据在SQLite持久化；事件和对象变更同事务 |
| main.py | API、错误处理、静态页面与用例连接 | 编辑采用expected_version；旧模型结果不覆盖新编辑 |

## 前端模块职责

| 文件 | 职责 |
|---|---|
| src/main.tsx | React入口、Ant Design中文与主题 |
| src/api.ts | 共享类型、HTTP请求封装、时间与来源显示 |
| src/App.tsx | 需求输入、字段核对、时间线、约束、资源、事件与回读 |
| src/styles.css | 三栏布局、状态配色、窄屏堆叠 |
| vite.config.ts | 开发期/api代理，避免前端接触供应商密钥 |
| playwright.config.ts | 浏览器回归配置，优先检测本机Edge |

App.tsx当前按状态、读写动作、字段编辑、工作台视图分段注释；后续页面扩展时再按业务组件拆分，避免本轮整理同时改变交互行为。

## 数据流

```text
用户原文
  → POST /api/needs
  → 真实模型或明确标记的演示／手工模式
  → Pydantic结构校验 + 原文证据校验
  → 用户核对与PATCH（expected_version）
  → POST /api/needs/{id}/plan-drafts
  → 匹配资料 + 确定性规则 + 无环依赖检查
  → SQLite保存草案与事件
  → 页面回读／刷新恢复
```

## 注释约定

- 模块文档字符串说明职责和输入输出，函数注释重点解释业务原因与边界。
- 对版本冲突、未知费用、证据校验、草案不等于预约等关键规则保留中文说明。
- 不给明显赋值逐行加注释，不把未完成的规划描述为已实现。
- 密钥、真实家庭资料及完整模型请求不写进注释和运行日志。

## 测试与工具

后端test_workflow.py覆盖接口和业务链路；test_model_profiles.py覆盖模型参数、输出截断、非法依据与修正次数。它们只使用临时数据库或内存HTTP模拟。

前端workbench.spec.ts覆盖可交互流程；live-result.spec.ts仅回读已存在的真实验收记录，没有该记录时跳过，不自动请求供应商。scripts/verify_live.py才会主动发起真实模型验收，可能产生初次请求与一次修正调用。

scripts/check_staged.py检查Git暂存内容，阻止依赖目录、运行数据或可识别凭证进入提交；结果只包含文件名，不打印凭证。
